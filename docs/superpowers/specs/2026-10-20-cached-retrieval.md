# MAR 检索缓存与 Qwen3.8-27B 实施规格

## 目标

在独立目录 `/home/c/czh/MAR_KDD_SearXNG` 建立可运行的 MAR 变体：复用已经备齐的两套作者测试集各 1,000 条，接入自部署 SearXNG 和持久检索缓存，推理模型使用官方 `Qwen/Qwen3.8-27B`。本地部署优先；若硬件不足，保留准确的模型接口配置并报告实际限制。

## 数据与运行边界

- 原项目 `/home/c/czh/MAR_KDD` 的代码、输出和数据不改动。新目录复制必要代码，图片和现有模型通过明确路径引用。
- 数据集、作者划分和真实标签保持不变。真实标签只进入评估，不进入检索查询和模型输入。
- 先复用作者图注和已有成功检索记录，再补缺失证据；每条记录保留来源、时间、图片哈希、状态。
- SearXNG 普通图片搜索与以图搜图须明确区分；只有后端实际支持的能力才能标记为反向搜图。
- 仅使用现有合法服务凭据，不创建账号规避额度。外部接口错误不伪装为零结果。
- 支持在线补缓存与只读缓存两种模式；只读缓存缺失须显式报告，不能偷偷调用收费服务。
- 持久保存网页/图片搜索结果和提取的最终证据，搜索缓存命中不得再请求同一搜索服务。查询、图片内容、检索参数或处理版本变化须分开缓存。
- SearXNG 与模型服务仅绑定本机端口；不停止其他项目服务，不占用已有端口。
- 全量缓存允许断点继续，失败有状态和重试入口；最终报告实际覆盖率，不将错误计入完成。

## 验收

1. 独立目录中有可运行入口、中文说明、SearXNG 配置和 Qwen3.8 模型配置。
2. SearXNG 服务通过本机 JSON 搜索实测，记录可用引擎与故障。
3. 对同一个网页/图片检索执行两遍，第二遍命中缓存且不调用后端；只读模式在无缓存时不联网。
4. 两套 1,000 条均生成证据清单，来源可追溯；已有证据导入和新增检索统计分开。
5. 准确报告模型是否下载、服务是否就绪、图像请求及 MAR 小样本是否实测通过；不将模拟测试当成模型实测。
